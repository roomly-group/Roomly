# Security Audit Findings – Status Summary

| Issue | Severity | Status | Notes |
|-------|----------|--------|-------|
| Missing rate limiting on authentication endpoints | High | **FIXED** | `loginLimiter` and `refreshLimiter` (express-rate-limit) are applied to `/api/login` (line 48) and `/api/refresh` (line 126) in `backend/src/routes/auth.ts`. Limiters defined in `backend/src/middleware/rateLimit.ts`. |
| Missing authentication checks on critical endpoints | High | **FIXED** | `requireAuth` middleware present on all listed routes: `POST /listings` (line 103), `GET /conversations` (line 130), `GET /conversations/:id/messages` (line 137), `POST /conversations/:id/messages` (line 155), `GET /dashboard/owner` (line 185) in `backend/src/routes/roomly.ts`. |
| Cookie SameSite=Strict may cause cross-origin issues | Medium | **FIXED** | `setAuthCookie` (line 16), `setRefreshCookie` (line 33), and `clearAuthCookies` (line 42) in `backend/src/routes/auth.ts` all use `sameSite: 'lax' as const`. |
| Weak password requirements: frontend enforces only minimum 6-character length (no complexity) | Medium | **FIXED** | Increased minLength to 8 and added complexity requirements (uppercase, lowercase, digit, special character) via pattern attribute on password inputs in `login.tsx` and `register.tsx`. |
| Lack of token revocation on logout | Medium | **FIXED** | Logout endpoint (`backend/src/routes/auth.ts` lines 222-233) calls `supabaseAuthClient.auth.signOut()` (line 225) to invalidate tokens on Supabase side before clearing HttpOnly cookies. |
| Information leakage in waitlist endpoint | Medium | **FIXED** | `/waitlist/me` endpoint (`backend/src/routes/waitlist.ts`) returns 404 when user record not found (line 55); no hardcoded fallback position 107. |
| CORS configuration too permissive | Medium | **FIXED** | `backend/src/app.ts` lines 36-44 define `allowedOrigins` based on environment and pass to `cors({ origin: allowedOrigins })`. Production origin restricted to `https://www.roomly.group`. |
| Potential CSRF risk in session hydration endpoint | Medium | **FIXED** | `/api/session` endpoint (`backend/src/routes/auth.ts` lines 325-351) requires `x-csrf-token: roomly` header (lines 327-330). SameSite is `lax` (see finding #3). |
| Unnecessary token exposure in response bodies | Low | **PARTIALLY FIXED** | Login (lines 110-116) and refresh (line 152) endpoints no longer return tokens. Verify endpoint (lines 199-208) still returns `access_token` and `refresh_token` in response body – needed for frontend to call `supabase.auth.setSession()` because HttpOnly cookies are inaccessible to JS. |
| Unnecessary fallback expiration in verify endpoint | Low | **FIXED** | Verify endpoint (`backend/src/routes/auth.ts` lines 178-214) treats JWT decode failures as invalid tokens (returns 401, line 213); no 1-hour fallback expiration remains. |
| Frontend token synchronization may expose tokens | Low | **FIXED** | `frontend/src/lib/supabase.ts` lines 47-64 sends tokens to backend endpoints (`/api/session` or `/api/refresh`) via same-origin HTTPS with CSRF token (`X-CSRF-Token: roomly`). Acceptable for synchronizing HttpOnly cookies with in-memory Supabase client. |
| Missing password confirmation strength check | Low | **FIXED** | Confirm-password input in `register.tsx` (lines 221-248) now has the same validation as password field (minLength 8 and pattern for complexity). |
| Potential XSS risk: dangerouslySetInnerHTML in chart component | Low | **FIXED** | `frontend/src/components/ui/chart.tsx` lines 97-125 uses `dangerouslySetInnerHTML` but passes all dynamic values through `sanitizeCssValue()` (lines 14-26). Includes comment explaining why usage is safe (lines 98-102) and notes that if config ever accepts user-controlled data, additional validation should be considered. |
